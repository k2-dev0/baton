# ASP / model-router

メインエージェントがSol／Astraを選び、同じタスクの途中で切り替えて作業を自動続行するローカル中継です。切り替えのための追加発言、別ターミナル操作、アプリ再起動は不要です。

判断基準の正本は配布元 `ai-agent-rules/skills/MODEL_SELECTION.md` に置きます。配布済みの指示からメインエージェントが読み、必要な場合だけ `switch_main_model` を呼びます。ルーターは文章の難易度判定、固定、手動／自動モード、理由の審査をしません。子エージェントのモデル・役割・権限は変更しません。

## 起動

登録済みの `asp` は、このリポジトリの `bin/model-router` を呼びます。実行時のディレクトリが作業場所になります。

```sh
asp check
asp app       # Desktop
asp           # CLI
asp --search  # CLIオプションも渡せる
```

CLIは専用のローカルApp Serverを起動します。Desktopの起動や、稼働中Desktopのサーバーを借りることは必要ありません。接続には実験的なUnix WebSocketを使います。

Desktopが通常起動済みで中継を通っていない場合、既存タスクを守るため起動を拒否します。初回導入・この修正版への更新時は、作業を整理してDesktopを手動終了し、`asp app` で起動してください。これは中継を接続するための初回操作であり、以降のモデル切り替えごとに再起動する必要はありません。

## 設定と移行

- `config.json` は本番用・Git管理対象外です。`config_sample.json` をひな形にします。本番ファイルにコメントは追加しません。
- `schemaVersion` は `2`。対象ディレクトリを `enabledRepositories` に絶対パスで登録します。既存の `setup-model-router` もこの配列を更新します。
- 配布元のモデル選択基準も対象プロジェクトへ既存の配布手順で更新してください。対象パスの登録だけでは、エージェントの判断基準は配布されません。
- Sol／Astraの既定の思考量はどちらもhigh。ユーザーが開始時に明示した思考量は維持し、専用ツールでのモデル変更時は切り替え先の既定値を使います。
- 旧 `mode`、`fixedModel`、`threadPins`、`escalatedThreads`、`requestModelPolicy`、`models`、`rulesVersion` は撤去済みです。旧形式の設定は黙って無視せず、移行を求めるエラーにします。
- 検証済みCodexは `0.153.4`。更新された別バージョンを、検証せず対応一覧へ追加しないでください。

変更ツールは、この修正版を通して開始する新規タスクへ登録します。登録済みタスクではCodexが履歴とツールを保存します。修正版導入前の既存タスクへ、再開だけでツールを後付けすることは現在の接続方式ではできません。初回は新規タスクを作成してください。

## 切り替えと安全動作

変更対象は、操作を呼んだタスクだけです。同じリポジトリ・同じDesktop内でも、タスクAのAstraへの変更はタスクBのモデルを変えません。Bの実行中の作業だけでなく、次の応答もB自身の設定を使います。共通設定へ「最後に選んだモデル」を保存して全タスクへ適用する処理はありません。

1. メインエージェントが切り替え先だけを指定します。変更理由は不要です。
2. 別のツール、承認待ち、バックグラウンドコマンドが残っていないことを確認します。残っていれば変更を拒否し、先に完了を待たせます。
3. 現在の実行区間を終了させ、終了応答と通知の両方を確認します。
4. Codexの正規の設定変更を行い、同じタスクにツールの処理結果を渡して、新モデルで残りの作業を開始します。ユーザー発言を偽造しません。

同じモデルの指定では中断しません。ユーザーの停止・設定変更と競合した場合はユーザー操作を優先します。切り替え途中の追加入力は送信済みと偽らず、未送信であることと再送の必要をエラーで知らせます。通信失敗や続行失敗を成功として記録しません。

権限、承認、作業環境はCodexが保持する最新設定を引き継ぎます。作業モードの指示、追加の文脈、回答形式も維持します。モデル変更ごとにエージェント設定ファイルを書き換えません。

実行中の生成モデルを直接置換する実験機能では、Sol→AstraがCodex側のレビュー要件の違いで拒否されました。その安全要件を解除せず、上記の正規の終了・続行手順を使っています。そのためCLIでは切り替え時に標準の「Conversation interrupted」が表示されますが、その後は自動続行します。成功通知を捏造してこの表示を隠してはいません。

## 記録と検証

タスク・適用モデルの永続化はCodex本体に任せます。ルーター独自の全タスク状態ファイルは使用しません。旧 `state.json` は読み込まず、削除もしません。診断ログは `~/Library/Application Support/codex-model-router/router.jsonl` です。

`CODEX_MODEL_ROUTER_CONFIG`、`CODEX_MODEL_ROUTER_STATE_DIR`、`CODEX_MODEL_ROUTER_INNER_CODEX` で試験用の設定・保存先・実行ファイルを指定できます。

```sh
npm test
npm run check
# 実際のモデルを使用し、利用枠を消費する試験
MODEL_ROUTER_LIVE=1 npm test -- -t '実機で同一タスク'
```
